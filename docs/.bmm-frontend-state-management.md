**Architecture:** Hybrid (TanStack Store + TanStack Query + React Contexts)

## Architecture Overview

### Why Hybrid?
- **TanStack Query:** Server state (API data) with automatic caching & sync
- **TanStack Store:** UI state requiring cross-tab synchronization
- **React Context:** Feature-specific providers (Confirm, Theme)
- **Local State:** Component-level state (useState, TanStack Form)

### Design Decision
**Only 1 global TanStack Store** - Most state is server-driven via TanStack Query, minimal UI state needs global persistence.

## Best Practices

### Query Keys
✅ **DO:** Use centralized `QUERY_KEYS` from `queryKeys.ts`
❌ **DON'T:** Hardcode query keys in components

### Store vs. Query
✅ **DO:** TanStack Store for UI state needing cross-tab sync
✅ **DO:** TanStack Query for server state
❌ **DON'T:** Duplicate server data in TanStack Store

### Optimistic Updates
✅ **DO:** Implement for create/update/delete mutations
✅ **DO:** Rollback in `onError`
✅ **DO:** Invalidate in `onSettled`

### Cache Invalidation
✅ **DO:** Invalidate hierarchically (`QUERY_KEYS.einsatz.all`)
✅ **DO:** Use `queryClient.invalidateQueries()` in `onSettled`
