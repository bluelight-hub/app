## Was war schwierig

### NestJS Provider Export Problem (CRITICAL)
**Problem:** NestJS kann nur Provider exportieren, die auch im selben Modul registriert sind. Konkrete Repository-Klassen waren nur als `useClass` für DI-Token Provider registriert, nicht als eigenständige Provider.

**Symptom:** Runtime-Fehler beim Modul-Import.

**Lösung:** Nur DI-Tokens exportieren, nicht konkrete Klassen:

```typescript
// ❌ FALSCH: Konkrete Klassen exportieren
exports: [PrismaQualifikationRepository]  // Funktioniert nicht!

// ✅ RICHTIG: Nur DI-Tokens exportieren
exports: [
  KRAEFTE_REPOSITORIES.QUALIFIKATION,
  KRAEFTE_REPOSITORIES.FAHRZEUGTYP,
  // ...
]

// Consumer nutzt:
@Inject(KRAEFTE_REPOSITORIES.QUALIFIKATION)
private readonly repository: IQualifikationRepository
```

**Learning:** Das ist eigentlich Clean Architecture konformer - Consumer kennt nur das Interface und den Token, nicht die konkrete Implementierung.

### Rate Limiting zu aggressiv
**Problem:** 10 Requests/Minute war viel zu niedrig für normale App-Nutzung. Bei jedem Route-Wechsel und Focus-Event feuert die App Requests → 429 Errors.

**Lösung:** Rate Limit auf 120/min (2 req/s) erhöht.

**Learning:** SPAs mit TanStack Query haben andere Request-Patterns als klassische Server-Rendered Apps. Rate Limits müssen das berücksichtigen.

## Key Learnings

### 1. NestJS DI Token Export Pattern (NEU - CRITICAL!)

```typescript
// In Infrastructure Module:
@Module({
  providers: [
    {
      provide: KRAEFTE_REPOSITORIES.QUALIFIKATION,
      useClass: PrismaQualifikationRepository,
    },
  ],
  exports: [KRAEFTE_REPOSITORIES.QUALIFIKATION], // NUR Token exportieren!
})
export class KraefteInfrastructureModule {}

// Consumer-Modul:
@Inject(KRAEFTE_REPOSITORIES.QUALIFIKATION)
private readonly repository: IQualifikationRepository
```

### 2. Rate Limiting für SPAs

| Kontext | Empfehlung |
|---------|------------|
| Admin Mutations | 10-20/min (strikt) |
| Read Endpoints | 120/min (2/s) für normale Nutzung |
| Bulk Operations | Eigenes Limit definieren |

### 3. Archive-Pattern (etabliert)

```typescript
// Domain Aggregate
archive(archivedBy: string): Result<void> {
  if (this.isArchived) {
    return Result.fail(ERROR_CODES.ALREADY_ARCHIVED);
  }
  this._props.archivedAt = new Date();
  this._props.archivedBy = archivedBy;
  return Result.ok();
}

restore(restoredBy: string): Result<void> {
  if (!this.isArchived) {
    return Result.fail(ERROR_CODES.NOT_ARCHIVED);
  }
  this._props.archivedAt = undefined;
  this._props.archivedBy = undefined;
  this._props.updatedBy = restoredBy;
  return Result.ok();
}
```

### 4. M:N Junction Table DIFF-BASED Sync

```typescript
// DIFF-BASED statt deleteMany+createMany
const existingIds = new Set(existing.map(q => q.qualifikationId));
const newIds = new Set(aggregate.qualifikationIds);

const toDelete = [...existingIds].filter(id => !newIds.has(id));
const toAdd = [...newIds].filter(id => !existingIds.has(id));

// Nur Deltas anwenden
if (toDelete.length > 0) await client.deleteMany({ where: { id: { in: toDelete } } });
if (toAdd.length > 0) await client.createMany({ data: toAdd.map(id => ({ ... })) });
```
