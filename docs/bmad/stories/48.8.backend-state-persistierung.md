### Auto-Save Strategy

[Source: docs/bmad/prd/lagekarte-prd.md#NFR6: State-Sync-Performance]

**Debounced Auto-Save:**
- **Trigger:** User makes change (POI placement, drawing)
- **Debounce:** 2 seconds of inactivity
- **Save:** TanStack Query mutation → Backend API
- **Sync:** Other devices see changes after reload

**Why 2 seconds?**
- Balance between responsiveness and server load
- Prevents excessive API calls during active editing
- Users expect auto-save (like Google Docs)

### TanStack Query Integration

[Source: docs/development/tech-stack.md#State Management & Data Fetching]

**Query Hook (Load State):**
```typescript
// packages/frontend/src/api/hooks/useLagekarteApi.ts
export const useLagekarte = (einsatzId: string) => {
  return useQuery({
    queryKey: ['lagekarte', einsatzId],
    queryFn: () => api.lagekarte().getLagekarte(einsatzId),
    networkMode: 'offlineFirst', // Enable offline-first mode
  });
};
```

**Mutation Hook (Save State):**
```typescript
export const useSaveLagekarteState = (einsatzId: string) => {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: (state: any) =>
      api.lagekarte().saveLagekarteState({ einsatzId, state }),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['lagekarte', einsatzId] });
    },
    networkMode: 'offlineFirst', // Queue mutations when offline
  });
};
```

### Debouncing with TanStack Pacer

[Source: docs/development/tech-stack.md#TanStack Pacer]

**Auto-Save Hook Implementation:**
```typescript
import { useDebouncedCallback } from '@tanstack/pacer';
import { useSaveLagekarteState } from '@/api/hooks/useLagekarteApi';

export const useLagekarteAutoSave = (einsatzId: string, state: any) => {
  const saveMutation = useSaveLagekarteState(einsatzId);

  const debouncedSave = useDebouncedCallback(
    (state: any) => {
      saveMutation.mutate(state);
    },
    2000 // 2 seconds debounce
  );

  // Call debouncedSave whenever state changes
  useEffect(() => {
    if (state) {
      debouncedSave(state);
    }
  }, [state]);
};
```

### Conflict Handling Strategy

[Source: docs/bmad/prd/lagekarte-prd.md#FR8: Lagekarten-State]

**Last-Write-Wins (MVP):**
- **Pro:** Simple, no versioning needed
- **Con:** Concurrent edits can overwrite each other
- **Mitigation:** Show warning in UI, document limitation
- **Future:** Add `Lagekarte.version` field for optimistic locking (v2)

**User Warning Text:**
```
⚠️ Die Lagekarte wird automatisch gespeichert. Bei gleichzeitiger Bearbeitung durch mehrere Nutzer kann es zu Datenverlust kommen. Koordinieren Sie Änderungen im Team.
```

### Offline-First Behavior

[Source: docs/development/tech-stack.md#TanStack Query]

**TanStack Query Offline Mode:**
- `networkMode: 'offlineFirst'` enables queueing
- Mutations queue when offline
- Retries automatically on reconnect
- User sees pending state (optimistic UI)

**Test Scenario:**
1. Disconnect WiFi
2. Place POI → Mutation queued
3. Draw shape → Mutation queued
4. Reconnect WiFi
5. TanStack Query retries → Mutations succeed
