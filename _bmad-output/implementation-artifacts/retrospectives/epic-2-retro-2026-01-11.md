## What Went Well

### 1. Konsistente Architektur-Patterns
- **Port-Adapter Pattern (Story 2.1):** Ermoeglicht plattform-agnostischen Code fuer Tauri und Web
- **TanStack Ecosystem:** Konsequente Nutzung von TanStack Store, Query, Router und Form
- **Result<T> Pattern (Backend):** Konsistent in allen Handlers angewendet

### 2. Hohe Test-Coverage
- **400+ Tests** ueber alle Stories hinweg
- **AAA Pattern** (Arrange-Act-Assert) mit Given-When-Then Kommentaren
- **Mock-Qualitaet:** Full Mocks mit Map-based Storage, keine echten Side Effects

### 3. Effektive Code Reviews
- **50+ Issues** fruehzeitig erkannt und gefixt
- **Kritische Bugs verhindert:**
  - Race Condition bei Invite-Code Exchange (Story 2.3)
  - Single-Instance Permission fehlt auf Windows/Linux (Story 2.4)
  - Redirect-Loop bei leerem Server-State (Story 2.6)

### 4. Wiederverwendbare Komponenten
- **ExpiredLinkError → OnboardingErrorCard:** Generische Error-Card fuer alle Szenarien
- **useExchangeInvite Hook:** Wiederverwendet in Stories 2.4, 2.5, 2.6
- **DeepLinkService:** Event-Emitter Pattern fuer lose Kopplung

### 5. Klare Dokumentation
- Jede Story mit vollstaendigem Dev Agent Record
- JSDoc Kommentare auf Deutsch
- README Updates fuer neue Features

## What Could Be Improved

### 1. E2E Tests fehlen teilweise
- **Story 2.4 Task 6:** E2E Tests fuer Deep Links erfordern .app Bundle (macOS-Limitation)
- **Story 2.5 Task 6:** Integration Tests auf Chrome MCP verschoben
- **Empfehlung:** E2E Test-Strategie fuer Tauri-spezifische Features definieren

### 2. Test-Flakiness bei Timing
- **Story 2.2:** Flaky Tests durch echte Timestamps → Fix mit `vi.useFakeTimers()`
- **Empfehlung:** IMMER Fake Timers fuer Date-Tests verwenden

### 3. Deprecated Zod APIs
- **Story 2.2:** `.uuid()`, `.url()`, `.datetime()` deprecated → Fix mit `.refine()`
- **Empfehlung:** Zod APIs regelmaessig auf Deprecations pruefen

### 4. Code Review Findings Pattern
Wiederkehrende Issues:
- DI Import Pattern (import type vs import) - immer wieder Fehler
- Console.log vergessen zu entfernen
- Missing Error Handling Cases
- **Empfehlung:** Pre-commit Hook fuer console.log, DI Import Check aktivieren

### 5. Story-Groesse variiert stark
- **Story 2.7:** 166 Tests (sehr gross)
- **Story 2.2:** 48 Tests (mittel)
- **Empfehlung:** Stories auf ~50-80 Tests begrenzen fuer bessere Review-Zyklen

## Lessons Learned

### Backend Patterns

| # | Lesson | Source |
|---|--------|--------|
| 1 | **Atomic Updates fuer Race Conditions:** Prisma `updateMany` mit conditional WHERE statt separatem read+write | Story 2.3 |
| 2 | **Result<T> konsistent:** NIEMALS Exceptions im Application Layer, NUR Result.fail() | Story 2.3 |
| 3 | **Rate-Limiting via @Throttle:** Einfach zu implementieren, funktioniert zuverlaessig | Story 2.3 |
| 4 | **DI Token Constants:** Zentralisiert in di-tokens.ts, niemals inline Strings | Story 2.3 |

### Frontend Patterns

| # | Lesson | Source |
|---|--------|--------|
| 5 | **TanStack Store External Actions:** Store-Funktionen ausserhalb des Konstruktors definieren | Story 2.2 |
| 6 | **Immutability:** IMMER `{ ...state }` spreads, niemals direkte Mutation | Story 2.2 |
| 7 | **Fire-and-forget Pattern:** In useEffect fuer async Operations (kein await in cleanup) | Story 2.4, 2.5 |
| 8 | **Zod .refine() statt deprecated APIs:** Fuer custom Validators mit klaren Fehlermeldungen | Story 2.2, 2.5 |
| 9 | **useMemo Selector Pattern:** Fuer Re-Render-Optimierung bei berechneten Werten | Story 2.2 |
| 10 | **Event-Driven Service:** Singleton mit EventEmitter fuer lose Kopplung | Story 2.4 |
| 11 | **TanStack Router validateSearch:** Search Params als first-class citizens mit Zod | Story 2.5 |
| 12 | **Session Storage fuer UI State:** z.B. Banner-Dismiss, nicht persistent | Story 2.7 |

### Testing Patterns

| # | Lesson | Source |
|---|--------|--------|
| 13 | **vi.useFakeTimers():** Fuer deterministische Date-Tests | Story 2.2 |
| 14 | **Full Mocks:** Map-based Storage statt echtes localStorage in Tests | Story 2.1 |
| 15 | **Error Path Testing:** IMMER alle Error-Pfade explizit testen | Story 2.1 |
| 16 | **jest.clearAllMocks() in beforeEach:** Mock-Reset vor jedem Test | Story 2.3 |
| 17 | **Test Structure:** ~25-30 Tests pro Layer (schema, service, hook, UI) | Story 2.5 |

### Tauri-spezifisch

| # | Lesson | Source |
|---|--------|--------|
| 18 | **Deep Links NICHT in Dev-Mode:** macOS erfordert vollstaendig gebuendeltes .app | Story 2.4 |
| 19 | **Single-Instance Plugin REQUIRED:** Windows/Linux spawnen sonst neue Instanz | Story 2.4 |
| 20 | **Platform Detection:** `isTauri()` fuer conditional Features | Story 2.7 |
